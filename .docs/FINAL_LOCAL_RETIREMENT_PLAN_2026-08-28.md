# 本地项目最终退役计划

## 目标

在不上传真实业务数据的前提下，先对不可从 GitHub 恢复的核心业务资料建立可验证的 AES-256-GCM 本地加密备份，再完成项目本地退役。

## 保留范围

- `data/input/pi`：真实 PI 与原始验收样本。
- `data/reference`：物料主数据、PI 提取规则、款式字典、模板和说明资料。
- `data/golden`：已知对照结果与验收参考。

## 实施计划

1. 确认 GitHub 远端、本地 HEAD 和工作区状态。
2. 在项目外创建专用备份目录，复制三类核心资料并生成逐文件 SHA-256 清单。
3. 使用随机高强度口令、PBKDF2-SHA256 和 AES-256-GCM 对完整备份加密，不保留明文中间包。
4. 从加密包解密至任务临时目录，核对数量、相对路径和逐文件 SHA-256，然后清理临时明文。
5. 将本轮退役记录明确暂存、提交并推送 GitHub，再核对远端 HEAD。
6. 向用户交付恢复口令；只有在用户明确确认已保存口令后，才将项目目录和项目 AppData 移入回收站。

## 禁止范围

- 不上传真实 PI、业务参考资料、物料数据或密钥。
- 不将恢复口令写入项目、Git、备份目录或报告。
- 不修改生产代码、测试、解析合同、字典内容或匹配数据。
- 不触碰冻结的 `Day01` 目录、GitHub 远端或与本项目非专属的模型缓存。

## 完成标准

- 加密备份、无密钥恢复脚本和非敏感校验说明位于项目目录外。
- 实际解密复验后，源文件与恢复文件的数量、路径和 SHA-256 完全一致。
- 明文中间包和临时恢复目录已清理。
- 退役记录已推送，本地与 GitHub `master` HEAD 一致。
- 用户已明确确认保存恢复口令，然后才执行本地回收站删除。
