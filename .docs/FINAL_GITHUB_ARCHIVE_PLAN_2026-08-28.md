# GitHub 最终归档计划

## 目标

将本项目可安全公开复现的完整 Git 仓库推送到当前已登录的 GitHub 账户，并用本地与远端 commit 一致性作为完成依据。

## 实施计划

1. 核对分支、HEAD、工作区、已跟踪文件和本地忽略项。
2. 检查 Git 对象完整性、历史文件范围、大文件与敏感信息风险。
3. 验证依赖锁和自动化测试，不调用真实 API、BGE-M3 或 FAISS 真实索引。
4. 只提交本轮必需的计划、开发日志和唯一 Gate 报告。
5. 按用户最终要求创建公开 GitHub 仓库，推送 `master` 及全部可达历史。
6. 比较本地 HEAD、远端跟踪分支和 GitHub 分支 HEAD，并复核最终工作区。

## 禁止范围

- 不提交或上传真实 PI、本地 Job、Sidecar、业务参考数据、物料库、向量索引或密钥。
- 不修改产品代码、字典、匹配逻辑或业务数据；仅允许修复本轮实际发现的 Windows LF/CRLF 测试兼容性阻断。
- 不触碰冻结目录。
- 本 Gate 不执行本地项目删除；删除必须在确认未上传业务数据的取舍和精确边界后单独执行。

## 完成标准

- Git 对象检查通过，暂存差异和敏感扫描无阻断项。
- 必要的可复现文件均处于 Git 跟踪范围；忽略的业务数据保持未上传。
- 定向验证或完整离线测试通过，结果如实写入报告。
- GitHub 仓库已创建且为公开，远端 `master` HEAD 与本地 HEAD 完全一致。
- 最终工作区无本轮遗留的未提交变更。
