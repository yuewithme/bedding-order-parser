# Gate 4B-R7 12份PI桌面端串行全量回归验收报告

## 1. 任务目标与执行边界

本轮目标是通过桌面快捷方式启动当前本地桌面版本，并按文件名不区分大小写升序串行处理正式12份PI，记录阶段耗时、结果完整性、匹配状态、资源占用和稳定性。

实际执行在第2份PI物料匹配阶段触发资源安全停止条件，因此形成部分验收报告。未修改业务代码、前端代码、匹配算法、配置、规则字典、物料主数据、FAISS、SQLite或Day01；未运行pytest、LLM、PyInstaller、Onedir或Onefile。

执行约束得到遵守：

- 只启动一个桌面应用实例。
- 同一时间只存在一个新任务。
- 任务通过该桌面实例的`/api/jobs`任务服务提交，没有直接调用解析器或匹配器函数。
- 轮询间隔为0.5秒，资源采样间隔为2秒。
- 没有重试失败PI，没有在验收中修改程序。

## 14. 发现的问题

### 阻断问题

1. **B-01：首次进入物料匹配时内存持续增长并越过双重安全阈值。** 第2份任务安全触发时工作集4.713 GiB、系统可用内存0.858 GiB；关闭确认等待中工作集继续达到约9.95 GiB。该问题阻止12份串行回归继续执行，也不允许直接进入LLM接入。

### 明确应修问题

1. **F-01：任务元数据原子写入存在瞬时访问拒绝。** 第1份任务在写入`job.json`时，临时文件替换目标文件发生`WinError 5`，导致业务解析尚未开始即失败。需要在下一Gate检查Windows文件占用来源和有限重试策略。
2. **F-02：启动时不处理无进程支撑的旧processing历史。** 本轮开始前已有一条2026-07-28遗留的processing记录，桌面启动后仍继续显示为处理中。需要设计可追溯的启动恢复或中断标记规则，不能静默删除。

### 性能问题

1. 模型与匹配资源在任务阶段加载后没有在安全停止请求到达时立即停止增长；确认关闭所需的人工交互窗口延长了高内存暴露时间。

### 无真值无法判断

1. 本轮没有生成匹配候选，无法评价物料推荐准确性、Top 5质量或原型综合分数。

### 正常业务缺失

未确定。没有足够完成记录区分正常无候选和处理失败。

### 已知限制

1. 状态API没有为字段提取和字典验证提供独立计时边界。
2. interrupted任务的`elapsed_seconds`保持`0.0`，只能使用控制端时间和时间戳记录实际持续时间。
3. 任务只有完成后才发布artifact映射；中断前已写出的三份JSON不能通过下载接口访问。
