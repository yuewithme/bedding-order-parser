## 2. 企业业务场景

本项目来源于床品外贸和供应链管理中的真实业务。企业接收客户订单或形式发票后，需要从复杂 Excel 文件中识别床品商品信息，并最终与企业物料库和 ERP 文件进行对比。

客户文件通常称为 PI，即 Proforma Invoice，中文为形式发票。PI 文件常以 Excel 工作簿形式提供，不同客户的模板差异很大，不能假定存在统一表头、统一字段名或固定商品明细区域。

## 3. 复杂 Excel 的典型问题

真实 PI 可能包含：

- 合并单元格；
- 多行表头；
- 表头位置不固定；
- 商品明细位置不固定；
- 没有明确序号；
- 中英文或其他多语言描述；
- 空白行和空白列；
- 同一单元格包含多个业务字段；
- 规格、尺寸、密度等信息混在描述中；
- 不同客户使用不同字段名称；
- 一张表中包含多种床品商品；
- 数据结构不规则；
- 公式单元格；
- 隐藏行或隐藏列；
- 多个工作表。

因此，项目不能在未查看真实样本前编造业务字段、固定 Schema 或商品抽取规则。

## 4. 完整系统最终目标

完整课题最终希望实现：

1. 上传并读取复杂 Excel PI；
2. 识别工作表、表头、订单元信息和商品明细区域；
3. 只提取 duvet cover，即被套类商品；
4. 输出稳定的结构化 JSON；
5. 使用 LLM 处理复杂和非标准表格语义；
6. 使用向量检索匹配企业物料库；
7. 向量检索计划采用 FAISS 和 BGE-M3 embedding；
8. 物料匹配结合规格、尺寸、密度等硬条件；
9. 输出企业物料编码；
10. 与 ERP 文件逐行对比；
11. 标记差异字段；
12. 提供结果预览与导出；
13. 后续可能使用 FastAPI 和简单前端；
14. 最终提供 Docker 运行说明和项目报告。

以上是长期目标，不代表当前仓库已经实现这些能力。

## 5. 当前实际范围

当前实际范围是 Gate 1 离线基线解析器。

Gate 1 的目标是从真实 PI Excel 中筛选被套商品，并输出用户指定的最终 20 字段 JSON。当前实现是离线规则基线，不接入 LLM、OpenAI API、FAISS、Embedding、FastAPI、前端、ERP 对比、Agent 或 Docker。

用户已经提供 Gate 1 本地样本和参考资料。真实企业资料保存在 Git 忽略的数据目录中，不得提交到 Git。当前基线解析器不得伪造物料编码或相似度，物料编码固定为空字符串，相似分数固定为 `0.0`。
